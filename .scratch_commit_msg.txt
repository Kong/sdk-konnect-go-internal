sdk: regenerate with session affinity and intelligent-balancer strategy unblocked

Regenerates on top of abd3dae8, which drops the hardcoded x-internal/
x-unstable dev-tier markers (and x-property-annotations entries) on the
session-affinity schema family and on BalancerIntelligentConfig's
`strategy` field, in addition to the existing runtime-version flip.

Verified in generated Go:
  - AIGatewayModelBalancerSessionAffinity now generates with ttl,
    storage, enabled fields; AIGatewaySessionAffinityStorage
    (local/redis discriminated union) also generates.
  - session_affinity is now wired onto all 7 balancer algorithms that
    reference it in the spec (round-robin, least-connections,
    lowest-latency, lowest-usage, priority, semantic, intelligent).
    consistent-hashing legitimately does not reference it.
  - AIGatewayModelBalancerIntelligentConfig's Strategy field is
    present (enum: weighted, margin), no longer stripped.
  - Classifier field unchanged: still only the model-reference variant
    (model, timeout, context_window) — platform-api#3930's current
    draft still defines no "custom" classifier variant.

Note: several balancer config types (round-robin, least-connections,
lowest-latency, lowest-usage, priority, intelligent) collapsed from
separate request/response (Output) types into a single shared type,
because their request and response shapes are now identical once
session_affinity's defaults apply symmetrically. The merged type kept
the "...Output" source filename as a generation artifact; the type
name itself is unchanged (e.g. AIGatewayModelBalancerIntelligentConfig).
This is a cosmetic consequence of the schema becoming symmetric, not a
behavior change — confirmed via `go build ./...` (clean).

This is still a local-only platform-api spec simulation of what we
expect the eventual 2.4 spec to look like; nothing here is pushed
upstream to platform-api.
